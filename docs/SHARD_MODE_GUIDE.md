# 子GAS分散（SHARD_MODE）運用手順書

対象: 美作市教育委員会 ICT担当（システム管理者）
版数: 拡張機能 1.6.4 / バックエンド `gas/Code.gs`

---

## 0. この機能は「いつ必要か」

**通常は不要です。既定は `SHARD_MODE = false`（1校1GAS）で、従来と完全に同じ動作をします。**

必要になるのは、**1つのGASで受ける負荷が Apps Script の上限に近づいたとき**だけです。

### 0-1. 実際の上限（ここを誤解しないこと）

| 項目 | 上限 | 補足 |
|---|---|---|
| **同時実行数（ユーザーあたり）** | **30** | これが本当の壁 |
| 同時実行数（スクリプトあたり） | 1,000 | 通常は到達しない |
| 1回の実行時間 | 6分 | Web アプリの1リクエストは通常 0.1〜0.5秒 |
| トリガー合計実行時間 | 90分/日（個人） / 6時間/日（Workspace） | **時間主導トリガーのみ**。Web アプリは対象外 |

> **「1日60分」という制限は存在しません。** Web アプリ（`doPost`）はトリガー実行時間の枠を消費しません。

### 0-2. 負荷の目安

端末は稼働中 1.5 秒ごとにハートビートを送ります。

| 規模 | 毎秒のリクエスト | 1実行200ms想定の同時数 | 判定 |
|---|---|---|---|
| 1クラス 40台 | 約 27 回/秒 | 約 5.3 | 問題なし |
| 1学年 80台 | 約 53 回/秒 | 約 10.7 | 問題なし |
| **1校 240台** | **約 160 回/秒** | **約 32** | **30 を超える＝要分散** |
| 1校 240台（3〜5ms化後） | 約 160 回/秒 | 約 0.8 | 問題なし |

**まず CacheService 最適化（実装済み）で足りるか確認してください。**
`processHeartbeat` はシート全読みをせず、キャッシュから 3〜5ms で応答します。
この状態で 240 台が収まるなら、**SHARD_MODE は不要**です。実行ログで実測してから判断してください。

### 0-3. 分散の構成

```
                    ┌──────────────────────────┐
                    │  親GAS（ハブ）            │
   教員コンソール ──▶│  ・教員ログイン/権限      │
   （この1画面のみ） │  ・端末一覧の「正」       │
                    │  ・ロック/規制/配信の「正」│
                    └────────┬─────────────────┘
                             │ クラス→子URLを返す／指示を伝達（fetchAllで並列）
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
        ┌──────────┐   ┌──────────┐   ┌──────────┐
        │ 子GAS A  │   │ 子GAS B  │   │ 子GAS C  │
        │ 5年1組   │   │ 5年2組   │   │ 6年1組   │
        └────▲─────┘   └────▲─────┘   └────▲─────┘
             │              │              │
          児童端末       児童端末       児童端末
        （1.5秒ごと）   （1.5秒ごと）   （1.5秒ごと）
```

**教員は親コンソールしか見ません。** 子GASの存在は教員からは見えません（「完全1画面」）。

## 1. 用語と保存場所

| 名前 | 保存先 | 内容 |
|---|---|---|
| `SHARD_MODE` | `Code.gs` の `CONFIG` | `true` でこのスクリプトが**親**になる |
| `SHARD_CHILD_MODE` | `Code.gs` の `CONFIG` | `true` でこのスクリプトが**子**になる |
| `SHARD_MAP_V1` | スクリプトプロパティ | クラス名 → 子GAS URL の対応表（JSON） |
| `SHARD_DEFAULT_URL` | スクリプトプロパティ | クラス不明時の受け皿となる子GAS URL（任意） |
| `SHARD_SECRET` | スクリプトプロパティ | 親⇔子の共有シークレット（`sk_` で始まる） |

いずれも **GAS の「プロジェクトの設定」→「スクリプト プロパティ」** に入れます。
スプレッドシートのセルではありません。

## 2. 導入手順（全体像）

作業順序を間違えると**全校の端末が通信できなくなります**。次の順で進めてください。

1. 子GASを必要数デプロイする（**先に子**）
2. 共有シークレットを生成し、全子GASへ設定する
3. 親GASにマッピングを設定する
4. 親GASを `SHARD_MODE = true` にする
5. 端末1台で動作確認 → 全校展開

> **順序が重要な理由:** 親を先に `SHARD_MODE = true` にすると、子GASが未準備のまま
> 端末に「存在しない子GASのURL」を配ってしまい、端末が通信できなくなります。

## 3. 子GASの準備

### 3-1. 子GASを何個作るか

**1クラス＝1子GAS** を基本とします。上限は 1クラス 40台です。

- 5年1組・5年2組・6年1組 … のように**クラス数だけ**用意する
- 目安: 1校あたり 6〜12 個
- 増やすときは、子GASを追加してマッピングに1行足すだけ（親の再デプロイ不要）

**同じ子GASを複数クラスで共有しても構いません。** 負荷が分散できていれば十分です。

### 3-2. 子GASの作成

1. 子GAS用のスプレッドシートを新規作成する
2. 「拡張機能」→「Apps Script」を開く
3. `gas/Code.gs` の内容を**そのまま全部**貼り付ける（親と同じファイル）
4. `CONFIG` の該当行だけ書き換える

```js
// 子GASではこうする
SHARD_MODE: false,        // ← 子は親ではない
SHARD_CHILD_MODE: true,   // ← これを true にする
```

5. 保存（Ctrl+S）
6. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**（または組織内）
7. 表示された **ウェブアプリのURL**（`.../exec` で終わる）を控える

> **子GASのURLは「新しいデプロイ」で構いません。** 端末が直接使うのは親のURLだけです。
> 子のURLは親のマッピングに書くので、差し替えも容易です。

### 3-3. 子GASのシート構成

子GASのスプレッドシートにも**端末一覧シートが必要**です。
`gas/Code.gs` を貼って保存すれば、初回アクセス時にヘッダーが自動作成されます。

子のシートには「その子へハートビートした端末」だけが並びます。
**児童の行が無くても一括操作は失敗しません**（親が指示と同時に行を作ります）。

## 4. 共有シークレット（`sk_`）の設定

親と子は**教員トークンではなく共有シークレット**で認証します。
シークレットが一致しない子は、親からの指示を**一切受け付けません**（安全側）。

### 4-1. シークレットを生成する

**親GASのスクリプトエディタ**で、次の関数を1回だけ実行します。

```js
function generateShardSecretForSetup() {
  const s = getOrCreateShardSecret();
  Logger.log('SHARD_SECRET = ' + s);
}
```

1. エディタ上部の関数選択で `generateShardSecretForSetup` を選ぶ
2. 「実行」
3. 「実行ログ」に `SHARD_SECRET = sk_xxxxxxxxxxxxxxxx` と出る
4. この値を**全子GASに同じものを設定**する

> 生成は冪等です。2回実行しても値は変わりません。
> **値を変えたいときだけ**、後述の「シークレット再発行」を行います。

### 4-2. 子GASへ設定する

各子GASの「プロジェクトの設定」→「スクリプト プロパティ」で:

| プロパティ | 値 |
|---|---|
| `SHARD_SECRET` | `sk_xxxxxxxxxxxxxxxx`（親と同一） |

### 4-3. シークレット再発行（漏洩時のみ）

親GASで:

```js
function rotateShardSecretForSetup() {
  PropertiesService.getScriptProperties().deleteProperty('SHARD_SECRET');
  const s = getOrCreateShardSecret();
  Logger.log('新しい SHARD_SECRET = ' + s);
  invalidateShardConfig();
}
```

実行後、**全子GASに新しい値を設定し直してください。**
再発行すると、旧シークレットの子は指示を受け取れなくなります。

## 5. マッピングテーブルの設定

### 5-1. 記述例（親GASのスクリプトプロパティ）

`SHARD_MAP_V1` に**JSON文字列**を入れます（1行で構いません）。

```json
{
  "5年1組": "https://script.google.com/macros/s/AKfycb...AAA/exec",
  "5年2組": "https://script.google.com/macros/s/AKfycb...BBB/exec",
  "6年1組": "https://script.google.com/macros/s/AKfycb...CCC/exec",
  "6年2組": "https://script.google.com/macros/s/AKfycb...DDD/exec"
}
```

**クラス名だけ**を書きます。学校名は含めません（親GASは1校＝1つです）。

### 5-2. 表記ゆれは自動で吸収されます

次の書き方はすべて同じクラスとして扱われます。

| 書いた表記 | 内部キー |
|---|---|
| `5年1組` | `5-1` |
| `５年１組`（全角） | `5-1` |
| `5-1` | `5-1` |
| `5/1` | `5-1` |
| `5年 1組`（空白入り） | `5-1` |
| `5組` | `5-1` |

端末一覧シートの「クラス」列が `5年1組` でも `５年１組` でも、
`5-1` に対応する子GASへ振り分けられます。

> `未設定` はどの子GASにも割り当てられません。
> クラス未設定の児童は親GASが受け持ちます（または `SHARD_DEFAULT_URL` へ）。

### 5-3. 既定URL（任意）

`SHARD_DEFAULT_URL` に子GASのURLを入れると、
**マッピングに無いクラスの児童もその子GASへ**回せます。

```
SHARD_DEFAULT_URL = https://script.google.com/macros/s/AKfycb...ZZZ/exec
```

- 入れない場合: マッピングに無いクラスは親GASが受け持ちます
- 入れる場合: クラス不明の児童も子へ分散されます

> **専科教員の取得が速くなる仕組み:** 対象クラスが1つだけの教員（専科など）は、
> **そのクラスを担当する子GASにだけ**問い合わせます。1クラス分の通信時間で済みます。
> このとき `SHARD_DEFAULT_URL` は取りこぼし防止のため常に対象に含まれます。

### 5-4. 設定の確認（管理API）

管理者でログインした状態で、次のアクションを叩くと現在の設定が見えます。

```json
{ "action": "get_shard_settings" }
```

返る内容（シークレットは伏字）:

```json
{
  "success": true,
  "settings": {
    "shard_mode": true,
    "child_mode": false,
    "classes": [
      { "class_name": "5年1組", "normalized": "5-1", "url": "https://.../exec" }
    ],
    "normalized_count": 4,
    "default_url": "",
    "secret_configured": true,
    "max_per_class": 40
  },
  "is_admin": true
}
```

保存もAPIで可能です（管理画面に設定UIは**設けていません**。教員画面を簡潔に保つため）。

```json
{
  "action": "save_shard_settings",
  "settings": {
    "classes": [
      { "class_name": "5年1組", "url": "https://.../exec" },
      { "class_name": "5年2組", "url": "https://.../exec" }
    ],
    "default_url": ""
  }
}
```

> URL は `http://` または `https://` で始まる必要があります。それ以外は拒否されます。

## 6. `SHARD_MODE = true` への切り替え

### 6-1. 前提チェック（重要）

切り替える前に、必ず確認してください。

- [ ] 子GASをすべてデプロイした
- [ ] 全子GASに `SHARD_CHILD_MODE = true` を入れた
- [ ] 全子GASに**同じ** `SHARD_SECRET` を入れた
- [ ] `SHARD_MAP_V1` のJSONが正しくパースできる（`get_shard_settings` で確認）
- [ ] 子GASのURLがすべて `.../exec` である

### 6-2. 切り替え

親GASの `Code.gs` を1行だけ変更します。

```js
// 変更前
SHARD_MODE: false,

// 変更後
SHARD_MODE: true,
```

### 6-3. 再デプロイ（**必ず既存デプロイを更新**）

1. 「デプロイ」→「**デプロイを管理**」
2. 使用中のデプロイの**鉛筆アイコン（編集）**をクリック
3. バージョンで「新バージョン」を選ぶ
4. 「デプロイ」

> ### 絶対に「新しいデプロイ」を押さないでください
> 新しいデプロイは**URLが変わります**。URLが変わると、全校の端末に配布済みの
> 管理ポリシー（`gas_url_map`）がすべて無効になり、**全校の端末が通信できなくなります。**
> 復旧には全校のポリシー再配布が必要です。

### 6-4. 動作確認

1. 端末1台で拡張機能の動作を確認（最終同期日時が更新されるか）
2. 教員コンソールで端末一覧が表示されるか
3. 一括ロックが1クラスで効くか
4. 問題なければ全校展開

## 7. 動作の仕組み（運用時に知っておくと役立つ点）

### 7-1. 端末側の通信先の切り替え

| タイミング | 端末の動き |
|---|---|
| 初回 | 親GASへハートビート → 応答に `assigned_gas_url` が入る |
| 2回目以降 | **子GASへ直接**ハートビート（1.5秒周期を維持） |
| 6時間ごと | 親へ再確認（クラス変更に追従） |
| 子へ3回連続失敗 | **親へ自動切り戻し**（端末が孤立しない） |
| 切り戻し後30分 | 再割り当てを保留（壊れた子との無限往復を防ぐ） |

端末側の保存先は `chrome.storage.local` です（管理ポリシーではありません）。
そのため**端末ごとに個別の設定作業は不要**です。

### 7-2. 教員コンソールの取得（`get_all`）

| 場面 | 動き |
|---|---|
| 単一クラス選択 | **クライアント側で絞り込み**。サーバー再取得なし（瞬時に切り替わる） |
| 全校・全学年 | 必要な子GASへ **`fetchAll` で並列**取得（12クラスでも待ち時間は1回分） |
| 専科教員（対象クラス1つ） | **該当する子GASにだけ**問い合わせ（最も速い） |
| 連続操作・自動更新 | **4秒キャッシュ**に当たる（子GASへの再通信なし） |

キャッシュは `dev_v`（書き込み版数）をキーに含めています。
ロック・配信・規制などの**書き込みをすると自動的に失効**するため、
操作直後に古い一覧が表示されることはありません。

### 7-3. 教員コンソールの稼働状態（`ka_active`）の伝達

端末は「教員コンソールが起動中」のときだけ 1.5 秒周期で同期します。
教員は親コンソールにしかログインしないため、**親が子へ稼働状態を配ります**。

- 稼働中（`true`）: **30秒に1回**へ間引き
- 解放（`false`）: **即時**

これが無いと、子GASは永久に「非稼働」と判断し、**分散した瞬間に全端末が同期停止**します。

### 7-4. 全校一括操作

「全校一括ロック」「全校一括URL配信」も、親から全子GASへ
**`fetchAll` で一斉に**伝達します（1回分の待ち時間）。

子のシートに対象児童の行が無い場合は、**指示と同時に行を作ってから**適用します。
行の作成に失敗した場合は、応答の `ensure_error` に理由が入り、
コンソールの操作結果から確認できます（**無言で失敗しません**）。

## 8. トラブルシューティング

### 8-1. 端末が同期しない

| 症状 | 確認すること |
|---|---|
| 全校で同期しない | 親GASのURLが変わっていないか（「新しいデプロイ」を押していないか） |
| 特定クラスだけ同期しない | そのクラスの子GASがデプロイされているか、URLが正しいか |
| 分散直後に止まった | 子GASの `SHARD_CHILD_MODE = true` になっているか |
| 子へ切り替わった直後に止まる | `SHARD_SECRET` が親子で一致しているか |

### 8-2. 教員コンソールに児童が出ない

- `SHARD_MAP_V1` のJSONが壊れていないか（`get_shard_settings` で確認）
- 子GASが「アクセスできるユーザー: 全員」になっているか
  （制限されていると親からの `fetchAll` が 302 でログイン画面を返し、JSONパースに失敗します）

### 8-3. 一括ロックが効かない

- `get_shard_settings` で `secret_configured: true` か
- 子GASの実行ログに `unauthorized` が出ていないか
- 応答の `shard` フィールドに `ensure_error` が出ていないか

### 8-4. 動作が遅い

- 実行ログで `get_all` の実行時間を確認（4秒キャッシュが効いていれば 100〜200ms）
- 子GASの数が多すぎないか（1校 6〜12 個が目安）
- 子GAS側の `processHeartbeat` が 3〜5ms で応答しているか

### 8-5. 元に戻したい（分散をやめる）

1. 親GASの `SHARD_MODE` を `false` に戻す
2. **既存デプロイを更新**（鉛筆アイコン → 新バージョン）
3. 端末は6時間以内に自動で親へ戻ります
   （すぐ戻したい場合は、端末の `chrome.storage.local` を消すか、翌朝の再起動を待つ）

> `SHARD_MAP_V1` を消すだけでも、親が割り当てを返さなくなるため端末は親へ戻ります。

- 子GASの「アクセスできるユーザー」を「自分のみ」にすると親から到達できません。
  「全員」または「組織内」にしてください（認証はシークレットで行います）。
- シークレットを記載したメール・チャット・共有ドキュメントは残さないでください。
- 異動等でICT担当が変わる場合は、シークレットを**再発行**してください。
