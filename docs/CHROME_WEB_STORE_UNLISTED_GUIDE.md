# Chrome ウェブストア「限定公開（Unlisted）」での配布手順 ＋ 児童端末ゼロ設定ガイド

本ドキュメントは、次の2つを実現する手順です。

1. 本拡張機能を **Chrome ウェブストアに「限定公開（Unlisted）」でアップロード**する。
2. **児童端末では何も設定しなくてもよい**状態にする（＝配布も設定も自動）。

> 結論：**ウェブストアで限定公開＋Google 管理コンソールで「強制インストール」＋ Managed Storage ポリシー配布**。
> これで児童は、インストールもID入力もGAS URL入力も一切不要になります。

---

## 0. 前提：配布方式の比較（なぜこの方法か）

| 配布方式 | 児童の設定 | ストア審査 | 自動更新 | 備考 |
|---|---|---|---|---|
| ① 開発者モードで手動読み込み | 必要 | なし | なし | 検証用のみ |
| ② `.crx` を自己ホスト（URLから追加） | 不要 | **なし** | 自前で | 最も手軽。ただし審査なし |
| **③ ウェブストア限定公開（本手順）** | **不要** | **あり** | **あり** | 信頼性・監査・自動更新◎ |

③を選ぶ最大の利点は **「審査済みの信頼できる配布」＋「自動更新」** です。教育委員会の説明資料としても「ウェブストア掲載」は安心材料になります。

---

## 1. 事前に必要なもの

- **Google アカウント**（開発者登録用。教育委員会の共用アカウントでも可）
- **初回のみ：開発者登録料 5 USD**（買い切り・クレジットカード決済）
  - <https://chrome.google.com/webstore/devconsole> → 規約同意 → 支払い
- **配布用のZIP**：`dist/extension.zip`（`bash scripts/package_extension.sh` で生成）
- **アイコン**：16/48/128px（`extension/icons/` に同梱済み）
- **審査用の説明文**：下記「5. 審査で聞かれること」をそのまま使えます

> ⚠️ **重要（審査の前提）**：Chrome ウェブストアでは **リモートコードの読み込みが禁止**されています。
> 本プロジェクトは `popup.html` から Tailwind CDN を除去し、自己完結の `popup.css` に置き換え済みです（v1.3.0）。
> 同様に `lock.html` / `blocked.html` も外部CDNを使っていません。**この状態を保ってください。**

## 2. アップロード手順（限定公開）

### ステップ 1：ZIPを作成

```bash
bash scripts/package_extension.sh     # → dist/extension.zip
```

### ステップ 2：開発者ダッシュボードで新規アイテム追加

1. <https://chrome.google.com/webstore/devconsole> にログイン
2. **「新しいアイテムを追加」** → `dist/extension.zip` をアップロード
3. アップロード完了後、**アイテムID（32文字）** が確定します（以降、更新でも不変）

### ステップ 3：ストアの掲載情報を入力（「ストアの掲載情報」タブ）

| 項目 | 入力例 |
|---|---|
| 名前 | Chromebook 児童端末管理クライアント |
| 概要 | 教育委員会が管理する児童端末向けの画面ロック・URL規制・一斉配信クライアントです。 |
| 詳細説明 | 教育委員会の管理下で、児童端末の集中管理を行うための拡張機能です。管理者の許可なく個人が利用することはできません。 |
| カテゴリ | 教育／仕事効率化 |
| 言語 | 日本語 |
| スクリーンショット | 1280×800 または 640×400 を1枚以上（ポップアップ／管理画面の画像） |
| ストアのアイコン | 128×128（`icons/icon128.png`） |
| プライバシーポリシーURL | 教育委員会の規程ページ、または下記「6. プライバシーポリシー例」を掲載したURL |

### ステップ 4：プライバシー（「プライバシー」タブ）

- **単一用途（single purpose）**：
  「教育委員会が、管理下の児童端末に対して、画面ロック・URL規制・一斉配信を一括実行するためのクライアント機能を提供すること。」
- **権限の使用理由（permission justification）**：下記「5. 審査で聞かれること」を貼り付け
- **データ使用（Data usage）**：該当項目にチェック（下記参照）

### ステップ 5：配布設定（「配布」タブ）— ここが限定公開

1. **公開範囲（Visibility）** を **「Unlisted（限定公開）」** に設定
2. 対象地域：日本（または全市）
3. **「審査のために送信（Submit for review）」** をクリック

> **Unlisted の意味**：ストアの検索結果には出ませんが、**リンクを知っている人／管理コンソールからは**インストールできます。
> 審査は「Public」と同じく受けます（信頼性の担保）。

### ステップ 6：審査通過後

- 審査は通常 **数時間〜数日**（権限が多いと数日〜1週間程度）
- 承認されると **公開（Published）** になり、アイテムIDでインストール可能になります

## 3. 児童端末を「ゼロ設定」にする（管理コンソール設定）

ウェブストアに載せただけでは、児童が自分で入れる必要があります。**管理コンソールで強制配布＋ポリシー配布**して初めてゼロ設定になります。

### 3-1. 強制インストール（児童は何もしなくてよい）

1. `admin.google.com` → **デバイス > Chrome > アプリと拡張機能 > ユーザーとブラウザ**
2. 対象OU（例：`児童生徒`／各校OU）を選択
3. **「＋」→「Chrome ウェブストアから追加」**（または「URLから追加」）
   - ウェブストアの場合：**アイテムID** または ストアURL を指定
   - ※ Unlisted のため、検索ではなく **アイテムIDで指定**します
4. 追加後、ポリシーを **「強制インストール」** に変更
   → 児童は**インストール不要・削除不可**になります

### 3-2. Managed Storage ポリシー配布（児童は入力不要）

同じく拡張機能の **「拡張機能のポリシー（Managed Storage）」** に、`dist/managed_policy.json` の中身を貼り付けます。

```json
{
  "gas_url_map": {
    "Value": {
      "英田小学校": "https://script.google.com/macros/s/＜英田小のID＞/exec",
      "大原小学校": "https://script.google.com/macros/s/＜大原小のID＞/exec",
      "江見小学校": "https://script.google.com/macros/s/＜江見小のID＞/exec",
      "勝田小学校": "https://script.google.com/macros/s/＜勝田小のID＞/exec",
      "勝田東小学校": "https://script.google.com/macros/s/＜勝田東小のID＞/exec",
      "第一小学校": "https://script.google.com/macros/s/＜第一小のID＞/exec",
      "北小学校": "https://script.google.com/macros/s/＜北小のID＞/exec",
      "土居小学校": "https://script.google.com/macros/s/＜土居小のID＞/exec",
      "英田中学校": "https://script.google.com/macros/s/＜英田中 のID＞/exec",
      "大原中学校": "https://script.google.com/macros/s/＜大原中のID＞/exec",
      "作東中学校": "https://script.google.com/macros/s/＜作東中のID＞/exec",
      "勝田中学校": "https://script.google.com/macros/s/＜勝田中 のID＞/exec",
      "美作中学校": "https://script.google.com/macros/s/＜美作中のID＞/exec",
      "樸学園":     "https://script.google.com/macros/s/＜樸学園のID＞/exec"
    }
  },
  "school_name": { "Value": "" },
  "student_id":  { "Value": "${USER_EMAIL}" }
}
```

- **`student_id: "${USER_EMAIL}"`** … ログイン中の児童アカウントが自動で児童IDに。**ID入力不要**
- **`school_name`** … 各校OUでその学校名に設定（`gas_url_map` の振り分けキー）。**学校選択不要**
- **`gas_url_map`** … 学校名→GAS URLの対応表。**URL入力不要**

### 3-3. ゼロ設定が成立する仕組み（本プロジェクトの実装）

| 児童がやること | 実際に誰が設定するか | 実装 |
|---|---|---|
| インストール | 管理コンソール（強制） | 管理コンソールの強制インストール |
| 児童ID入力 | 不要 | `${USER_EMAIL}` ＋ `chrome.identity`（`identity.email` 権限）で自動取得 |
| 学校選択 | 不要 | OUごとの `school_name` ポリシー |
| GAS URL入力 | 不要 | `gas_url_map` ポリシー ＋ `resolveGasUrl` が自動振り分け |

> 📌 **`identity.email` 権限について**：`chrome.identity.getProfileUserInfo()` でログイン中のメールを取得するには、
> manifest に **`identity.email`** 権限が必要です（v1.3.0 で追加済み）。
> これが無いと空文字が返り、児童IDが自動取得できません。

### 3-4. Gemini等の無効化（任意・推奨）

ブラウザ本体のGeminiは拡張機能からは消せないため、管理コンソールの組織ポリシーで無効化します
（詳細は `docs/ADMIN_CONSOLE_SETUP.md` の「ステップ5」）。

## 5. 審査で聞かれること（そのまま使える回答例）

ウェブストア審査では、権限の正当性とデータ利用について説明を求められます。

### 権限の使用理由

| 権限 | 理由（回答例） |
|---|---|
| `host_permissions: <all_urls>` | 児童端末で開かれる**任意のWebページ**上で、画面ロックの表示とURL規制（許可/禁止）を行う必要があるため。 |
| `tabs` | 現在開いているタブのURLを取得し、教員コンソールへ「閲覧状況」として報告するため。 |
| `storage` / `storage.managed` | 管理コンソールから配布されるポリシー（GAS URL・学校名）を読み取るため。 |
| `alarms` | 一定間隔でサーバーと同期し、教員の指示を児童端末へ反映するため。 |
| `identity` / `identity.email` | ログイン中の児童Googleアカウントを自動取得し、児童IDとして名簿と突合するため。 |

### データ使用（Data usage）回答

- 収集するデータ：**認証情報（Googleアカウントのメール）**、**Web閲覧アクティビティ（現在のURL）**、**個人識別情報（氏名・学校・クラス）**
- 用途：**教育委員会による端末管理（画面ロック・URL規制・見守り）のみ**
- 第三者提供：**なし**（データは教育委員会のGoogle組織内にのみ保管）
- 広告・分析目的：**なし**
- 暗号化：**あり（HTTPS）**

### 単一用途

「教育委員会が管理下の児童端末を一括管理（画面ロック・URL規制・一斉配信）するクライアント機能」

## 7. 更新（バージョンアップ）の手順

1. `extension/manifest.json` の `"version"` を上げる（例 `1.3.0` → `1.3.1`）
2. `bash scripts/package_extension.sh` で `dist/extension.zip` を再作成
3. 開発者ダッシュボード → 対象アイテム → **「パッケージ」→「新しいパッケージをアップロード」**
4. 「審査のために送信」→ 承認されると **全端末へ自動更新**（児童・教員の操作不要）

> アイテムIDは不変のため、管理コンソール側の設定変更は不要です。

## 8. よくある質問

**Q. Unlisted と Private の違いは？**
A. Unlisted は「リンク/IDを知っていれば誰でも」、Private は「同一ドメイン内のみ」。教育委員会で配るなら **Unlisted** が扱いやすい（組織外のテスト端末にも入れられる）。

**Q. 児童が自分で拡張機能を外せる？**
A. 管理コンソールで「強制インストール」にすれば**外せません**。

**Q. ウェブストア経由でも Managed Storage は使える？**
A. 使えます。むしろ**ストア拡張機能＋Managed Storage が最も標準的**な構成です。

**Q. 児童が個人のGoogleアカウントでログインしたら？**
A. 学校組織のポリシーが適用されません。**学校配布の教育用アカウント**でのログインを徹底してください。

**Q. 審査でリジェクトされたら？**
A. よくある原因は「リモートコード」と「権限理由の不足」。本プロジェクトはリモートコードを除去済みなので、権限理由を丁寧に記載すれば通過しやすくなります。

**Q. 5ドル以外に費用は？**
A. ウェブストアの配布自体は無料です（初回の開発者登録料のみ）。
