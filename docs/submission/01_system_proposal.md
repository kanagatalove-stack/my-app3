## 1. 提案の要旨

本市では、児童生徒1人1台端末（Chromebook）の整備が進み、授業および家庭学習における活用が定着しつつあります。一方で、学習に資さないサイトへのアクセス、授業時間外の利用、端末の私的利用といった課題に対し、教員が個別に対応する負担が増大しております。

本提案は、既存の **Google Workspace for Education** 環境および **Chrome 拡張機能**のみで構成され、**新たなサーバ機器の導入を要しない**端末管理システムの導入を提案するものです。本市14校（東粟倉小学校を除く市域小中学校）を対象に、以下を実現します。

1. **時間割に連動した自動的な利用制限**（予約スケジュール制御）
2. **教員による即時制御**（画面ロック・画面情報の取得）
3. **学校間・学年間のデータ完全分離**（他校への干渉を構造的に防止）
4. **教員の運用負担の軽減**（単一画面からの一括管理）

## 2. 導入背景および目的

### 2.1 現状の課題

| 区分 | 課題 | 現行運用上の影響 |
|---|---|---|
| 利用時間 | 授業時間外・就寝時間帯の利用を止められない | 生活習慣への影響、保護者からの相談増 |
| アクセス先 | 学習に資さないサイトへの接続を都度指導 | 教員の授業中断、指導の属人化 |
| 端末状態 | 児童が何を表示しているか把握できない | 事後対応となり、指導機会を逸する |
| 運用負荷 | 端末ごと・学級ごとの個別設定が必要 | 設定作業の工数増、設定漏れの発生 |
| 情報管理 | 児童の利用履歴がどこに蓄積されるか不明瞭 | 説明責任の観点で懸念 |

### 2.2 導入目的

- **適切な利用管理**: 学習目的に沿った利用を、児童の操作に依存せず担保する
- **教員の負担軽減**: 個別指導ではなく、仕組みによる自動制御へ移行する
- **説明責任の確保**: 収集する情報を必要最小限に限定し、保管場所と権限を明確化する（詳細は「個人情報保護および情報セキュリティ管理説明書」に記載）
- **既存資産の活用**: 追加のサーバ・ライセンス購入を最小化し、財政負担を抑制する

### 3.2 各層の役割

| 層 | 実体 | 主な役割 | 保持する情報 |
|---|---|---|---|
| **親（ハブ）** | 各校1つの GAS Web アプリ + スプレッドシート | 教員画面の提供、名簿管理、予約の登録・承認、子GASへのポリシー配信、予約の展開計算 | 端末一覧、予約、画面情報 |
| **子（スポーク）** | 学級単位の GAS Web アプリ | 端末からのハートビート受託、展開済み予約の保持・配信 | 展開済み予約キャッシュ（PropertiesService） |
| **端末** | Chrome 拡張機能 v1.6.4 | 受信した制御指示の適用、画面ロック、URLフィルタリング | 端末ローカルの設定値のみ |

### 3.3 設計上の要点

- **1校 = 1 完全独立環境**: 各校のスプレッドシートおよびGASプロジェクトは物理的に分離されており、他校のデータを参照する経路を持ちません。これにより、ある校の設定変更や障害が他校へ波及する構造的リスクを排除しています。
- **親子間の役割分離**: 「ロック・規制・配信の正（正本）」は親に置き、子は**配信された結果を保持して端末へ返す**役割に限定します。教員は常に1つの画面のみを操作すれば足ります。
- **伝播はプロパティ経由・シート書き込みなし**: 親から子への予約伝播は **PropertiesService** に対してのみ行われ、**子スプレッドシートへの行書き込みは行いません**。これにより、子側シートの整合性問題と書き込み競合を構造的に回避しています。

## 4. 主要機能一覧

### 4.1 機能一覧表

| # | 機能区分 | 機能名 | 概要 | 利用者 |
|---|---|---|---|---|
| F-01 | 予約制御 | 予約スケジュール登録 | 対象（学校／学級／児童個人）、日付範囲、繰り返し（単発・毎日・毎週）、開始・終了時刻を指定して予約を作成する | 教員・管理者 |
| F-02 | 予約制御 | 画面ロック予約 | 指定時間帯に端末をロック状態へ遷移させる | 教員・管理者 |
| F-03 | 予約制御 | URL許可・規制リスト予約 | 指定時間帯に許可URLリスト（ホワイトリスト）または規制URLリスト（ブラックリスト）を適用する | 教員・管理者 |
| F-04 | 予約制御 | 予約の取消・手動解除 | 予約レコードは保持したまま「取消」（以後無効）または「解除」（今回のみ無効）を実行する。監査ログ保全のため行削除は行わない | 教員・管理者 |
| F-05 | 予約制御 | 定期実行の展開 | 繰り返し予約を期間内の実日時に展開し、子GASへ配信可能な形式に変換する（既定14日先まで、同時有効5件まで） | システム |
| F-06 | 即時制御 | 即時画面ロック | 予約とは独立に、対象端末を即時にロックする | 教員・管理者 |
| F-07 | 即時制御 | 画面情報の取得 | 対象端末へ撮影要求を発行し、端末が取得した画面情報を閲覧する（取得は要求時のみ） | 教員・管理者 |
| F-08 | 即時制御 | 一斉表示（ブロードキャスト） | 全対象端末または指定範囲へ指定URLを一斉表示させる | 管理者 |
| F-09 | 分離構造 | マルチスクール分離 | 学校単位でスプレッドシート／GASを分離し、他校データへの非干渉を保証する | システム |
| F-10 | 分離構造 | 学年・学級分離 | 学級単位で子GASを分割し、処理と保持データを学級単位に閉じる | システム |
| F-11 | 分離構造 | 教員スコープ制御 | 教員は自校・自担当学級の範囲のみ操作可能とする（範囲外は拒否） | システム |
| F-12 | 負荷対策 | 直列分散ハートビート | 端末の問い合わせを学級単位の子GASへ分散し、同時実行数の集中を回避する | システム |
| F-13 | 負荷対策 | 稼働連動ポーリング | 教員画面の稼働中のみ高頻度同期（1.5秒）、非稼働時は送信を停止する | システム |
| F-14 | 負荷対策 | ローカルフォールバック | 子GASが応答しない場合、既定の親GASへ自動的に接続し直し、端末の機能停止を防ぐ | システム |
| F-15 | 可観測性 | 到達ログ | 端末からの全リクエストを受付冒頭で記録し、通信到達の有無を確実に判別可能とする | 運用者 |
| F-16 | 可観測性 | 監視・注意検知 | 学習に関係のないサイトの検知を記録し、教員画面に表示する | 教員 |

### 4.2 予約スケジュール制御の仕様

| 項目 | 仕様値 | 備考 |
|---|---|---|
| 展開対象期間（既定） | 14日先まで | 設定により変更可能 |
| 同時有効ウィンドウ上限 | 5件 | 端末側の処理負荷を考慮した上限 |
| 繰り返し種別 | 単発（NONE）／毎日（DAILY）／毎週（WEEKLY） | 曜日指定可 |
| 時刻基準 | 日本標準時（UTC+9）固定 | 実行環境のタイムゾーンに依存しない実装 |
| 対象種別 | 学級一括／児童個人 | — |
| 取消と解除の区別 | 取消＝レコードは残し無効化／解除＝当該回のみ無効化 | 行削除は行わない（監査ログ保全） |

### 4.3 リアルタイム手動制御の仕様

| 機能 | 動作 | 制約・配慮 |
|---|---|---|
| 即時画面ロック | 教員操作により対象端末へロック指示を配信 | 予約制御とは独立して動作 |
| 画面情報の取得 | 教員が要求した時点でのみ撮影・送信 | **常時監視は行わない**（押下時のみ）。取得画像はサイズ上限を設け、超過分は受理しない |
| 一斉表示 | 指定URLを対象端末へ一斉表示 | 管理者権限に限定 |

**画面情報取得に関する設計方針**: 本機能は「教員が明示的に要求した場合のみ」実行され、常時キャプチャやバックグラウンド収集は行いません。これは、プライバシー配慮および通信量・保存容量の抑制を目的とした設計判断です。ただし、Chrome の特権ページ（`chrome://` 系）表示中はブラウザの仕様上取得できないため、その場合は「取得できなかった」旨の状態のみを記録します。

### 4.4 ネットワーク負荷軽減策

| 施策 | 内容 | 効果 |
|---|---|---|
| 親子分散 | 学級単位の子GASへハートビートを分散 | 単一実行への同時実行集中を回避 |
| 稼働連動 | 教員画面の稼働中のみ1.5秒周期、非稼働時は送信停止 | 非使用時の通信量を実質ゼロに抑制 |
| 段階的再確認 | 非稼働へ遷移した直後の短時間のみ低頻度で再確認、その後停止 | 再稼働の検知と通信抑制の両立 |
| キャッシュ活用 | 名簿・設定・予約を短時間キャッシュ | スプレッドシート読み取り回数の削減 |
| 応答の軽量化 | 予約は展開済み形式で配信し、端末側で再計算しない | 端末処理と応答サイズの削減 |

### 5.1 必要環境

| 区分 | 要件 | 備考 |

| 端末ポリシー | Chrome 管理コンソール（Managed Storage）によるポリシー配布 | 未配布の場合の代替手段あり（後述） |
| ネットワーク | インターネット接続（HTTPS） | 学校LAN環境 |

### 5.2 拡張機能の仕様（v1.6.4）

| 項目 | 内容 |
|---|---|
| マニフェスト | Manifest V3 |
| 要求権限 | ストレージ、アラーム、タブ制御、スクリプト実行等（必要最小限） |
| ポップアップUI | なし（教員画面はGAS Web アプリ側で提供） |
| 通信先 | 管理コンソールで配布されるGAS Web アプリURL |
| 設定の優先順位 | ①親から割り当てられた子GAS URL → ②学校別URLマップ → ③共通URL → ④ビルド時に埋め込む既定URL |

### 5.3 ポリシー未配布端末への配慮

Managed Storage ポリシー（`gas_url` / `gas_url_map`）が未配布の端末では、通信先が未確定となり機能しません。本システムでは次の三段構えで対処します。

1. **既定URLへのフォールバック**: 拡張機能に既定の接続先を保持し、ポリシー未配布でも初回同期を成立させる
2. **初回同期の強制**: 稼働判定に先行して初回のみ必ず1回送信し、親から割り当てURLを取得する
3. **明示的な診断記録**: 接続先が皆無の場合は「接続先未設定」として記録・警告し、無言の停止を排除する

> **【重要・ご確認事項】** 上記1の「既定URL」は、導入時に貴委員会の親GASのデプロイURLを設定する必要があります。設定値は1箇所に集約されており、導入作業工程にて投入いたします。未設定の場合は診断記録により明示的に検出されます。

## 8. 前提条件および制約

1. 本システムは **Google Workspace for Education** および **Google Apps Script** の提供状況に依存します。これらの仕様変更・サービス停止により影響を受ける場合があります。
2. 端末側の制御は **Chrome 拡張機能**により実現されるため、拡張機能が無効化・削除された端末では制御が及びません。管理コンソールによる強制インストールを推奨します。
3. 端末の**ネットワーク未接続時**は、最後に受信した制御状態が継続します。新たな制御の反映には接続が必要です。
4. Chrome の特権ページ（`chrome://` 系）および一部のブラウザ内部ページでは、技術的制約により画面情報の取得およびURL制御の一部が制限されます。
5. 本提案書に記載の機能は、**別途提示する見積書・利用規約・SLA合意書と一体**で効力を有します。
