## 1. 本説明書の目的と位置づけ

本説明書は、美作市教育委員会（以下「甲」）が導入する **Chromebook児童端末管理システム（Hub-Spoke構成）**（以下「本システム」）について、取り扱う個人情報の範囲、保管場所、アクセス制御、安全管理措置および契約終了時の消去手順を明らかにするものです。

本説明書は、個人情報の保護に関する法律（平成15年法律第57号）、学校教育法、教育委員会が定める情報セキュリティポリシー、および文部科学省「教育情報セキュリティポリシーに関するガイドライン」の趣旨に沿って作成しています。

本説明書は「ソフトウェア利用規約・SLA合意書」の一部を構成します。

## 2. 基本原則

本システムの設計および運用は、次の5原則に基づきます。

| # | 原則 | 内容 |
|---|---|---|
| 1 | **必要最小限の取得** | 教育目的の達成に必要な情報のみを取得し、常時収集を行わない |
| 2 | **学校単位の完全分離** | 1校 = 1 独立したスプレッドシート／GASプロジェクトとし、他校からの参照経路を持たない |
| 3 | **甲の環境内に閉じる** | データは甲の Google Workspace for Education 環境内に保管し、乙は独立した複製を保有しない |
| 4 | **通信の暗号化** | 端末とサーバ間の通信はすべて HTTPS（TLS）による |
| 5 | **説明可能性** | いつ・誰が・何を取得したかを記録し、甲が説明できる状態を保つ |

## 3. 取り扱う情報（個人情報の範囲）

### 3.1 情報の種類と利用目的

| # | 情報の種類 | 具体例 | 利用目的 | 保管先 |
|---|---|---|---|---|
| P-01 | 児童識別子 | 児童ID（メールアドレス形式 例：`1607002@city-mimasaka.ed.jp`、または数字ID `1607002`） | 端末と名簿の対応付け、制御指示の宛先特定 | スプレッドシート「端末一覧」 |
| P-02 | 児童氏名 | 名簿に登録された氏名 | 教員画面での識別表示 | スプレッドシート「端末一覧」 |
| P-03 | 所属情報 | 学校名、学年・学級名 | 学級単位の一括制御、権限スコープの判定 | スプレッドシート「端末一覧」 |
| P-04 | 端末利用状況 | 現在開いているURL、最終同期日時 | 学習状況の把握、制御状態の確認 | スプレッドシート「端末一覧」 |
| P-05 | 画面情報 | 教員の要求時に取得した画面のキャプチャ画像（Base64） | 要求時点の表示内容の確認 | スプレッドシート「画面情報」 |
| P-06 | 注意検知情報 | 学習に関係のないサイトの検知フラグ・理由・URL・検知日時 | 指導の契機の把握 | スプレッドシート「端末一覧」 |
| P-07 | 教員識別情報 | 教員のメールアドレス、氏名、所属校、役割、担当学級 | 認証、操作権限の判定、操作記録 | スプレッドシート「教員マスタ」 |
| P-08 | 予約情報 | 予約者、対象、日時、制限内容 | 予約制御の実行、監査ログの保全 | スプレッドシート「スケジュール管理」 |

### 3.2 取得しない情報（明示的排除）

本システムは、次の情報を**取得しません**。

| # | 取得しない情報 | 理由 |
|---|---|---|
| 1 | 常時の画面キャプチャ・画面録画 | プライバシー配慮。画面情報は教員の明示的な要求時のみ |
| 2 | キーストローク・入力内容 | 教育目的に不要 |
| 3 | カメラ・マイクの映像音声 | 教育目的に不要 |
| 4 | 位置情報 | 教育目的に不要 |
| 5 | 閲覧履歴の全件蓄積 | 「現在開いているURL」のみを保持し、履歴を蓄積しない |
| 6 | 私的アカウントの認証情報 | 取得しない |
| 7 | 生体情報 | 取得しない |

### 3.3 画面情報（P-05）の取扱いに関する特記

画面情報は、個人情報の性質上、最も慎重な取扱いを要する項目です。本システムでは次のとおり設計しています。

| 項目 | 仕様 |
|---|---|
| 取得契機 | **教員が管理画面で「画面情報取得」を明示的に操作した時点のみ** |
| 常時収集 | **行わない**（バックグラウンドでの定期取得機能を持たない） |
| 対象範囲 | 操作時に対象として選択された児童の端末のみ |
| データ形式 | PNG／JPEG／WebP の Base64 文字列 |
| サイズ上限 | 45,000 文字（超過分は受理せず、エラーとして返却） |
| 保持件数 | 児童1名につき1件（新規取得時に上書き。履歴を蓄積しない） |
| 技術的制約 | Chrome の特権ページ（`chrome://` 系）表示中は取得不可。この場合は「取得できなかった」旨の状態のみを記録し、画像は保存しない |
| 保存先 | 甲のスプレッドシート「画面情報」（児童ID／更新日時／MIMEタイプ／画像データ） |

> **【重要な設計判断】** 画面情報は**上書き方式**であり、過去の画像を蓄積しません。これにより、保存される個人情報を最小限に保ちつつ、教員が「現在の状態」を確認するという目的を達成します。

## 4. 通信の暗号化

### 4.1 通信経路

| 経路 | プロトコル | 暗号化 | 備考 |
|---|---|---|---|
| 端末（拡張機能）→ GAS Web アプリ | HTTPS（TLS 1.2 以上） | あり | Google が終端。証明書は Google 管理 |
| 親GAS ⇔ 子GAS | HTTPS（TLS 1.2 以上） | あり | Google のサーバ間通信 |
| 教員ブラウザ → GAS Web アプリ | HTTPS（TLS 1.2 以上） | あり | `google.script.run` 経由 |
| GAS → スプレッドシート | Google 内部 | あり | 同一テナント内 |

**平文（HTTP）による通信は行いません。** 本システムが生成・受信する URL はすべて `https://` で始まることを検証しており、`http://` の接続先は無効として破棄します。

### 4.2 認証方式

本システムは、利用場面に応じて2種類の認証を用います。

| 認証方式 | 用途 | 方式 | 有効期限 |
|---|---|---|---|
| **教員トークン** | 教員画面からの操作（一覧取得、予約登録、即時制御等） | HMAC-SHA256 署名付きトークン。ペイロード（教員メール・氏名・所属・役割・担当学級・有効期限）を Base64 エンコードし、サーバ側の秘密鍵で署名。改ざん検知可能 | 発行から **24時間** |
| **共有シークレット** | 親GAS → 子GAS のポリシー伝播 | 親子間で共有する秘密文字列（`SHARD_SECRET`）。リクエスト本文に含め、子側で照合 | 静的に保持（ローテーション可能） |

**トークンの検証プロセス**（教員操作時）:

1. トークンを「ペイロード部」と「署名部」に分割する
2. サーバ側でペイロード部を再署名し、受信した署名部と**完全一致**するか照合する（不一致＝改ざんとみなし拒否）
3. ペイロードの有効期限（`exp`）を現在時刻と比較し、期限切れを拒否する
4. 有効な場合のみ、ペイロード内の役割・所属・担当学級を用いて**操作権限を判定**する

> **【設計上の要点】** 教員の権限判定は、トークン内の署名済み情報に基づきます。クライアントから送信された「私は管理者である」といった主張は信頼しません。また、担当学級外への操作は**サーバ側で拒否**します（画面側の制御に依存しません）。

## 5. データ分離構造

### 5.1 学校間の分離

本システムは、**1校 = 1 完全独立環境** を原則とします。

```
┌─────────────────────────────────────────────────────────┐
│  英田小学校                                               │
│  ・GASプロジェクト（独立）                                │
│  ・スプレッドシート（独立）                                │
│  ・共有シークレット（学校固有）                            │
└─────────────────────────────────────────────────────────┘
              ↕ 参照経路なし
┌─────────────────────────────────────────────────────────┐
│  大原小学校                                               │
│  ・GASプロジェクト（独立）                                │
│  ・スプレッドシート（独立）                                │
│  ・共有シークレット（学校固有）                            │
└─────────────────────────────────────────────────────────┘
```

| 分離の対象 | 実装 |
|---|---|
| スクリプト（プログラム） | 学校ごとに独立した GAS プロジェクト |
| データ（名簿・予約・画面情報） | 学校ごとに独立したスプレッドシート |
| 認証情報 | 学校ごとに独立した共有シークレット |
| 実行主体 | 学校ごとのデプロイ（他校の実行ログに混入しない） |

**他校データへの非干渉保証**: 各校の GAS プロジェクトは、他校のスプレッドシートIDを保持せず、他校のURLを呼び出す経路も持ちません。したがって、**構造的に他校データへアクセスすることができません**（アクセス権設定に依存しない、実装レベルの分離）。

### 5.2 学年・学級間の分離（Hub-Spoke構成）

各校の内部は、親（ハブ）と学級単位の子（スポーク）に分割されます。

| 層 | 保持するデータ | 保持しないデータ |
|---|---|---|
| **親GAS** | 全校の名簿、予約の正本、画面情報、教員マスタ | — |
| **子GAS** | 展開済み予約キャッシュ（自校・自学級分のみ） | 名簿の正本、他学級の予約、画面情報 |

**子GASへの伝播方式**: 親から子への予約伝播は **Google Apps Script の PropertiesService（スクリプトプロパティ）に対してのみ**行われます。

> **【確定仕様】子スプレッドシートへの行書き込みは行いません。** 子GASは受け取った展開済み予約をプロパティに保持し、端末からの問い合わせに応じて返す役割に限定されます。これにより、子側シートの整合性問題、書き込み競合、および不要なデータ複製を構造的に回避しています。

### 5.3 教員の操作スコープ制御

| 役割 | 参照可能範囲 | 操作可能範囲 |
|---|---|---|
| 管理者（ADMIN） | 自校の全学級 | 自校の全学級 |
| 教員（TEACHER） | 自校の担当学級 | **自校の担当学級のみ** |
| 他校の教員 | 自校のみ | 自校のみ（他校は不可視） |

- 教員は**自校以外のデータを参照できません**（学校名によるスコープ判定）。
- 教員は**担当学級以外の予約を登録・変更できません**（サーバ側で拒否）。
- 児童個人を対象とする予約についても、対象児童が担当学級に属するかを照合します。

### 5.4 学校間集約における非干渉

複数校の状況を一覧する機能（教育委員会側での横断確認）は、**各校のデータを読み取って実行時に集約**する方式です。

> **【確定仕様】集約結果を親スプレッドシートへ書き戻すことは行いません。** 集約はメモリ上（実行時のみ）で完結し、新たなデータ複製を作りません。これにより、集約機能自体が個人情報の第二の保管場所となることを防いでいます。

## 6. 安全管理措置

### 6.1 組織的安全管理措置

| # | 措置 | 内容 |
|---|---|---|
| O-01 | 責任者の明確化 | 甲は本システムの個人情報管理責任者を定める |
| O-02 | 権限の最小化 | 教員アカウントは担当学級の範囲に限定。管理者は必要最小限の者に付与 |
| O-03 | 退職・異動時の措置 | 甲は退職・異動の都度、教員マスタの更新およびトークンの失効を行う |
| O-04 | 操作の記録 | 予約の登録・取消・解除は行削除せず保持し、監査ログとして機能する |
| O-05 | 委託先の監督 | 乙は甲データの独立した複製を保有しない（第7節） |

### 6.2 人的安全管理措置

| # | 措置 | 内容 |
|---|---|---|
| H-01 | 研修 | 甲は利用者に対し、個人情報の取扱いおよび本システムの適正利用に関する研修を行う |
| H-02 | 乙の従業者管理 | 乙は、業務上知り得た甲データを目的外に使用しない旨を従業者に周知する |
| H-03 | 禁止事項の周知 | 本システムを人事評価・素行調査目的に利用しないことを、利用規約第6条で明記 |

### 6.3 技術的安全管理措置

| # | 措置 | 内容 |
|---|---|---|
| T-01 | 通信の暗号化 | 全通信を HTTPS（TLS）で実施（第4節） |
| T-02 | 認証と署名検証 | HMAC-SHA256 によるトークン署名検証。改ざんを検知し拒否 |
| T-03 | 有効期限 | 教員トークンは24時間で失効 |
| T-04 | 認可のサーバ側実施 | 権限判定はサーバ側で実施し、画面側の制御に依存しない |
| T-05 | 学校単位の物理分離 | 独立したスクリプト・スプレッドシート・秘密鍵（第5節） |
| T-06 | 入力値の検証 | 画像データの形式検証、サイズ上限（45,000文字）の適用 |
| T-07 | URL検証 | 接続先URLが `https://` で始まることを検証。不正なURLは破棄 |
| T-08 | 到達ログ | 端末からの全リクエストを受付冒頭で記録し、通信の有無を確実に判別可能 |
| T-09 | 最小権限の要求 | 拡張機能の権限は機能遂行に必要な最小限（Manifest V3） |
| T-10 | 監査可能性 | 取消・解除を「無効化」として実装し、レコードを削除しない |

### 6.4 物理的安全管理措置

| # | 措置 | 内容 |
|---|---|---|
| P-01 | 保管場所 | 甲の Google Workspace for Education（Google のデータセンター）。甲の契約に基づく |
| P-02 | 端末の管理 | 端末は甲が管理する Chromebook。乙は端末に個人情報を蓄積しない |
| P-03 | 出力物の管理 | 教員が画面を印刷・保存する場合、甲の規程に従う |

> **【注記】** データの物理的な保管は Google のデータセンターに依存します。その安全管理は Google の責任範囲であり、Google Workspace for Education の契約条件および Google のセキュリティ認証（ISO/IEC 27001 等）に基づきます。乙は甲との契約範囲において、アプリケーション層の安全管理措置を担います。

### 6.5 データの保管場所（一覧）

| データ | 保管先 | 形式 | 保持期間 |
|---|---|---|---|
| 端末一覧（P-01〜P-04、P-06） | 甲のスプレッドシート「端末一覧」 | 行データ | 名簿に在籍する間 |
| 画面情報（P-05） | 甲のスプレッドシート「画面情報」 | Base64（児童1名1件、上書き） | 次回取得まで／契約終了まで |
| 教員マスタ（P-07） | 甲のスプレッドシート「教員マスタ」 | 行データ | 在職する間 |
| 予約情報（P-08） | 甲のスプレッドシート「スケジュール管理」 | 行データ（無効化により保持） | 契約終了まで（監査ログ目的） |
| 展開済み予約 | 子GAS の PropertiesService | JSON 文字列 | 次回伝播まで（揮発的） |
| キャッシュ | GAS の CacheService | 短時間のみ | 最大5分程度（自動消滅） |

> **PropertiesService の容量制約**: 1プロパティあたり約9KBの上限があるため、伝播データは分割・圧縮して送信します。上限超過時は送信を見送り、端末は最後に受信した状態を維持します。

## 7. 乙（提供者）によるデータの取扱い

| 項目 | 内容 |
|---|---|
| 甲データの保有 | **乙は甲データの独立した複製を保有しません**。データは甲の Google Workspace 環境内にのみ存在します |
| アクセス | 乙は、甲から明示的に依頼された保守作業の範囲でのみアクセスします |
| 開発環境への複製 | 行いません。検証には架空のテストデータを使用します |
| バックアップ | 乙によるバックアップは行いません。バックアップは甲の Google Workspace の機能（Vault 等）に依存します |
| 再委託 | 甲の書面承諾なく再委託しません（利用規約第22条） |
| 漏えい時の対応 | 乙の責めに帰す漏えいを認識した場合、速やかに甲へ通知し、被害拡大防止および再発防止に協力します |

## 8. 契約終了時のデータ消去手順

本システムの契約が終了した場合、次の手順を実施します。作業は**甲の主導**で行い、乙が手順書を提供して支援します。

### 8.1 消去手順

| # | 手順 | 実施者 | 内容 | 確認方法 |
|---|---|---|---|---|
| 1 | 利用停止の周知 | 甲 | 利用者へ本システムの利用停止を周知する | 周知文書の保管 |
| 2 | 拡張機能の削除 | 甲 | Chrome 管理コンソールから拡張機能の強制インストール設定を解除し、端末から削除する | 管理コンソールの設定画面 |
| 3 | 端末側データの消去 | 甲 | 端末のローカルストレージに残存する設定値（児童ID、制御状態等）を消去する。端末の再ログインまたは設定リセットにより実施 | 端末の設定確認 |
| 4 | GAS プロジェクトの削除 | 甲 | 対象校の親GAS・子GAS プロジェクトをゴミ箱へ移動し、完全削除する | Google Apps Script の管理画面 |
| 5 | スクリプトプロパティの消去 | 甲 | 削除前または削除時に、プロパティ（展開済み予約、共有シークレット等）が消去されることを確認する | プロパティ画面 |
| 6 | スプレッドシートの削除 | 甲 | 「端末一覧」「スケジュール管理」「画面情報」「教員マスタ」等の全シートを含むファイルをゴミ箱へ移動し、完全削除する | Google ドライブの管理画面 |
| 7 | 共有シークレットの破棄 | 甲 | 学校ごとの共有シークレットを無効化する（プロジェクト削除により達成） | 手順4・5と同時 |
| 8 | 削除完了の記録 | 甲 | 実施日、対象校、実施者、確認結果を「削除完了報告書」に記録する | 報告書の保管 |
| 9 | 乙による確認 | 乙 | 甲の削除完了報告書を確認し、乙側に複製が存在しない旨を書面で表明する | 確認書の交付 |

### 8.2 消去の対象と非対象

| 対象 | 消去の要否 | 備考 |
|---|---|---|
| 端末一覧・画面情報・教員マスタ | **要** | 個人情報を含むため必ず消去 |
| スケジュール管理 | **要** | 予約者情報を含むため消去 |
| GAS スクリプトプロパティ | **要** | 展開済み予約、共有シークレット |
| GAS のキャッシュ | 不要（自動消滅） | 最大5分程度で消滅 |
| Google ドライブのゴミ箱 | **要**（完全削除） | ゴミ箱に残存する限り復元可能なため |
| 甲の Google Workspace のバックアップ | 甲の規程による | Vault 等の保持ポリシーに従う |
| 乙の開発環境 | 該当なし | 甲データを保有しないため |

### 8.3 消去完了の期限

| 項目 | 期限 |
|---|---|
| 手順1〜7の完了 | 契約終了日から〔30〕日以内 |
| 削除完了報告書の提出 | 手順完了後〔10〕営業日以内 |
| 乙の確認書の交付 | 報告書受領後〔10〕営業日以内 |

### 8.4 部分終了の場合

対象校の一部のみが契約を終了する場合（例：学校統廃合）、当該校についてのみ上記手順を実施します。他校のデータには影響しません（学校単位の物理分離による）。

## 9. インシデント対応

### 9.1 対応体制

| 段階 | 内容 | 担当 | 目標時間 |
|---|---|---|---|
| 1. 検知 | 異常の検知（ログ、問い合わせ、外部からの指摘） | 甲または乙 | — |
| 2. 通報 | 検知者が直ちに管理責任者へ通報 | 検知者 | 直ちに |
| 3. 初動 | 影響範囲の把握、拡大防止措置（該当機能の停止等） | 甲・乙 | 〔4〕時間以内 |
| 4. 甲への報告 | 乙は甲へ第一報を提出 | 乙 | 認識から〔24〕時間以内 |
| 5. 調査 | 原因・影響範囲・漏えいの有無の調査 | 甲・乙 | 〔7〕日以内に中間報告 |
| 6. 是正 | 再発防止策の実施 | 乙 | 調査完了後〔30〕日以内 |
| 7. 最終報告 | 調査結果および再発防止策の書面報告 | 乙 | 是正完了後〔10〕営業日以内 |

### 9.2 個人情報の漏えい等が生じた場合

1. 甲は、個人情報の保護に関する法律第26条に基づく個人情報保護委員会への報告および本人への通知について、その要否を判断し、必要な手続を行う。
2. 乙は、甲の判断および手続に必要な情報（発生時期、原因、影響範囲、対象者数等）を提供し、協力する。
3. 乙は、原因が乙の責めに帰す場合、再発防止策を実施し、その内容を書面で甲に報告する。
